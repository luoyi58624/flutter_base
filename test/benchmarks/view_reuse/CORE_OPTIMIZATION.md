# 底层重建优化复测

实现提交 `33509a6` 保持 ElView、ElListenableBuilder 的公开签名不变。ElView 在普通文字配置更新时保留文本环境；ElListenableBuilder 在默认 select 的通知入口跳过等值结果，同时让父配置、继承环境和重新激活正常使缓存失效。

使用与原基线相同的 24 节点、每轮 12 次操作、正反顺序两轮参数。100 项基准通过，取得 264 组结果、3,168 个样本；另有 15 项监听器行为回归、62 项文本相关回归及 14 项选区/滚动复用回归通过。定向分析通过。原始摘要见 [optimized-core-2026-11-12.jsonl](optimized-core-2026-11-12.jsonl)，优化前见 [BASELINE.md](BASELINE.md)。

## 工作量变化

表中次数是一轮 12 次操作的累计，两轮工作计数一致。

| 场景 | 指标 | 优化前 | 优化后 |
| --- | --- | ---: | ---: |
| ElView 相同参数新配置 | 文本环境构建 | 288 | 0 |
| ElView 改变文字 | 文本环境构建 | 288 | 0 |
| ElView 改变文字 | 实际布局 | 288 | 288 |
| 默认标量 select，等值通知 | 监听器 Element 构建 | 288 | 0 |
| 默认标量 select，等值通知 | select 求值 | 288 | 288 |
| 默认标量 select，选中值改变 | select 求值 | 288 | 576 |
| 默认标量 select，同帧变化再还原 | 监听器 Element 构建 | 288 | 288 |
| 默认标量 select，同帧变化再还原 | 业务 builder | 0 | 0 |
| 自定义 List 值比较，等值通知 | 监听器 Element 构建 | 288 | 288 |

等值数据的默认筛选现在可以避免监听器自身及业务子树重建，但通知分发和 select 仍有成本。该结果要求没有其他配置或环境变化使节点变脏。自定义 `shouldRebuild` 仍在 build 阶段执行，保留等值主动重建与上次观察值的语义，不能套用默认路径的零构建结论。

变化通知需要先求值，再在 build 读取同帧最终值，所以 select 调用增加。已进入脏队列的变化随后还原，仍会消费一次 Element build；本次没有通过取消脏队列或改变同帧合并语义来省掉它。selector 应当是简单、无副作用的数据读取，复杂计算需要另行评估。

这些是带探针的无头 debug 动作加 pump 墙钟，不是真机帧耗时。前后来自不同运行，JIT、GC 与调度仍影响时间；确定性工作量更能说明优化做了什么。

## 正确性边界

- 文本环境继续订阅 MediaQuery 和 SelectionContainer；缩放、粗体、文字间距及换父正确更新，图标与文本切换重新选择环境参数。
- 真正变字仍排版，选区内容、文本通知与回收列表的高度变化继续正确。
- 父级替换 builder/child、builder 读取的 Inherited 配置改变，两个原有语义观察都已由旧内容变为新内容，`semantic_gap` 为 false，并由行为回归测试要求新内容。
- 自定义谓词、同帧最终值、监听源转移、GlobalKey 换父、reassemble、重入通知和异常后恢复均有回归覆盖。

这份报告只评价底层改动。实际业务页面的上层优化及其官方对照另行复测，不能把微基准时间直接换算成整页收益。
