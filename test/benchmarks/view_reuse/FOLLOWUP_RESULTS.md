# 业务复用补充优化与外卖视觉修正（2026-11-12）

本轮继续处理第一批之外的业务重建问题，并修正外卖字号、信息组织和商品区比例。公开 API 保持不变；ElListenableBuilder 用于筛选实际展示字段，既有 ElView / recycler 底层优化继续生效。

## 外卖视觉修正

店标为 72×72，店名 17 号；评分、销量、配送和标签集中在右侧。标签按内容自然宽度排列，大字时换行，单个标签文字仍为一行。商品方图改为 96×96、名称 14 号、价格 18 号；所有商品共用随字号计算的高度，长名称单行省略。红包栏宽 72，分成标题、金额与使用说明、底部领取提示；暗色单独保证金额颜色可读。

仍使用普通 ElCard / Row / Column / Wrap / LayoutBuilder 和 ElImage。窄网格省略红包栏，为横向商品保留空间。没有重新引入专用 RenderObject、手动画图或图片流管理。

无头截图使用真实中文字体检查了信息层次、标签宽度、红包比例和商品对齐；布局回归覆盖 320/390 宽度、1.6 倍字号、暗色、官方与回收列表/网格、触摸及辅助操作。截图是视觉检查产物，不用像素相等替代行为测试。

## 工作量结果

业务滚动每模式 32 样本；局部更新每模式 16 样本。下列是相同测试参数的前后累计工作，创建与已有节点重建分别计数。

| 实时聊天，回收模式正文更新 | 1464 | 332 | 全局 Element 重建 |
| 订单，两种模式各 16 次进度更新 | 592 | 488 | 每模式全局 Element 重建 |

| 复杂卡片演示，回收模式滚动 | 400 | 364 | 全局 Element 重建 |
| 复杂卡片演示，回收模式滚动 | 768 | 408 | Widget 配置变化 |

官方网格缓存的是相同几何下的 SliverGrid 和 delegate，**新进入窗口的 1488 个 Element 仍正常创建**。网格与瀑布流入口的官方分支都得到上述工作量改善；回收分支本轮工作量未变。这项优化同时改善官方对照，不能把旧版官方的冗余刷新算成 recycler 固有优势。

聊天将正文进度、播放/完成状态、单步禁用状态分开订阅，不再让每次正文变化刷新三组按钮。复杂演示卡片保留说明、图标和排版，图片与地点按实际字段筛选。矩形相同颜色换绑的叶子保持配置，但当前连续滚动样本颜色确实改变，因此其累计重建数没有下降。

订单保留单个进度监听器，在当前通知来源的闭包内复用同阶段状态文字；0、处理中、100 的边界切换仍更新，来源或主题变化重新建立缓存。正常推进仍配置数值和进度行，但保留其 Element / RenderObject。32 次滚动的回收模式重建维持 1104、配置变化维持 1744；官方新增 Element 维持 2592。局部更新收益没有增加滚动与挂载的节点工作。

文档仍是 ElSliverList 常驻文档与 SliverList 惰性对照，**不是 recycler 文档**；每节通知只驱动勾选和源码叶子，目录定位与展开后的高度恢复保留。尖峰示例只稳定普通行和列表配置，真实忙等、注入时机、脚本轨迹及取消逻辑未优化掉；测试全部使用工作函数替身。

## 首屏记录创建

新增独立创建基准：390×800、2 次热身、3 次采样，图片在计时外预热。每次全新页面默认进入 recycler；随后官方模式测的是同一批记录的容器切换，不能叫官方首次创建。

| 页面 | 首屏业务记录数：前 → 后 | 首次页面 pump 中位数：前 → 后 |
| --- | ---: | ---: |
| 复杂卡片 | 10000 → 2 | 68.179 → 60.452 ms |
| 复选列表 | 10000 → 12 | 79.697 → 80.166 ms |

三轮记录数量一致。主要收益是初始对象和文案分配减少，**没有证据说明所有页面首次耗时都变快**。完整逻辑数量仍为 10000；记录随首次访问创建并缓存，离屏选择和统计仍按业务 ID 保留，卸载后清空。

首次滚入新记录仍要生成文案，缓存会随访问增长；这不是固定内存占用方案。官方自然高度 SliverList 的远跳可能布局中间记录，不能套用 recycler 直接定位的成本要求。新增测试分别验证官方近跳/回访和 recycler 远跳，并独立检查未访问 ID 的业务状态；原有跨模式定位与选择回归保留。

## 验证与解释边界

本轮涉及的聊天、订单、卡片、选择、文档、尖峰、复杂演示、网格与外卖均有定向行为验证。没有跑全仓测试、前台应用或真实尖峰工作，也没有热重载或附加用户应用。未经修改的媒体和商品优化保留上一阶段结果，嵌套滚动示例仍按其常驻嵌套演示目的保留，没有强行改成 recycler。

验收包括 20 个修改 Dart 文件的定向静态分析；外卖行为与布局、聊天/订单/动态流、卡片/选择、文档/尖峰/复杂演示/网格的相关测试通过。文档目录定位在局部通知实现完成后另行复验；订单最终轻量实现的 6 项相关回归及单场景基准另行通过。

最终业务数据为 9 场景、88 组 / 704 样本；前对照为 8 场景、80 组 / 640 样本，外卖采用修正后新布局，因此只记录当前官方/回收对照，不作旧新布局速度比。创建基准另有前后各 4 组 / 12 个样本，文档和尖峰有前后各 6 条局部构建记录。

计时为带探针的 flutter_tester debug 动作加 pump 墙钟。不同运行中多组时间同时上下波动，例如相同工作量的 cards、selection 滚动本轮更慢，网格两入口的计时趋势也不一致；因此不声称全场景耗时下降，也不换算成真机帧率。优先依据确定性的构建、配置变化和业务记录数量评价收益。

原始日志中身份快照仅覆盖主滚动宿主，而全局构建探针也包含控制栏；因此聊天控制栏的收益主要反映在全局重建，不能要求宿主配置差异也同比下降。

最终订单复测曾被另一会话尚未完成的事件模块修改阻止编译，等待后第一次重试恢复。其数据在事件模块更新后采集，相关依赖指纹单独保存；其余场景保留此前有效测量，不将跨运行的墙钟差异全归于订单实现。

## 复现入口

在 `example/` 下以单进程低优先级运行短测试：

```powershell
$taskProcess = [Diagnostics.Process]::GetCurrentProcess()
$taskProcess.PriorityClass = 'BelowNormal'
flutter test test/sliver_business_performance_test.dart --no-pub --concurrency=1 --timeout 30s --reporter expanded --dart-define=BUSINESS_PERF=true --name '业务页面基准 (cards|selection|orders|liveChat|grid|masonry|complex|rectangles|takeaway)'
flutter test test/scroll_records_creation_performance_test.dart --no-pub --concurrency=1 --timeout 30s --reporter expanded --dart-define=BUSINESS_CREATION_PERF=true
flutter test test/scroll_rich_document_reuse_test.dart test/scroll_spike_test.dart --no-pub --concurrency=1 --timeout 30s --reporter expanded
```

创建和局部计数分别输出 `RECORDS_CREATION_RESULT` 与 `SPECIAL_REUSE_RESULT`。局部测试默认断言优化后的稳定身份；`SPECIAL_REUSE_BASELINE=true` 仅供旧实现采样，不作为最终验收参数。
