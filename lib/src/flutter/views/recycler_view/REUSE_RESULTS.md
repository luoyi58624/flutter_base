# 结构复用优化执行结果

日期：2026-11-06。基线为 `ac9ff5b`，对照本轮完成后的实现。所有自动验证均为 Windows 无头 `flutter test`，没有启动应用窗口、接管用户应用或操作手机。

**确定收益是工作量与驻留结构减少；五轮主机计时没有达到预定的稳定差异门槛，不能报告整体提速百分比或手机 FPS。**

## 已落实的改动

- El 样式过渡和关键帧按需订阅 TickerMode，覆盖隐藏、恢复、首次隐藏、换父、forceFrames 与释放；普通无动画 ElView 不增加 TickerMode 订阅。
- ElModelValue 的普通 value 回灌同帧显示，自身不因帧后补发再构建一次；保留外部观察者安全通知，补齐同值、重入规范化、同帧切换绑定通道与卸载测试。
- 跨记录换绑采用 holder 局部作用域，ElStyle 过渡、starting 入场、移动开关和确定进度直接到目标状态。同 ID 更新仍播放正常过渡，其他 holder 与可见的不确定进度、加载关键帧不受影响。
- 两端 Checkbox、Radio 使用轻量品牌视觉。复选示例删除 generation Key，固定事件包装不再随标题重建。
- 隐藏 holder 通过 HeroMode 排除旧标签，保留可见 Hero 导航；Timer/订阅仍由业务 attach、detach 与 recycle 生命周期负责。
- 同批结构通知合并到下一次几何读取/布局再扫描一次类型，保留类型依赖位置、总数量的 Adapter 契约。预算时钟仅提供内部测试接缝，生产模式不读取测试覆盖。数据更新期间保持已经存在的弹性越界，明确定位仍进入合法范围。
- 设置页新增跨页面帧耗时记录器，可复制完整 JSON。采样期间不刷新统计界面，显式窗口内超过 100ms 的停顿完整保留，并接收引擎延迟尾批。

对照树同时包含同一轮布局内暂存复用的改进，因此下面的整体计时不能拆分归因到某一个优化。

## 可重复的工作量变化

修改前后使用相同操作；旧版本失败的回归也保留了失败前输出的计数。

| 场景 | 基线 | 完成后 | 变化 |

| 加载关键帧和有限过渡进入隐藏池后的待执行动画回调 | 2 个，仍请求帧 | 0 个，不请求帧 | 消除隐藏动画的持续调度 |
| 真实复选行跨记录且勾选状态改变 | 新增 25、移除 25 个 Element | 新增 0、移除 0 | 该次换绑不再重挂复选视觉 |

原本已达到的工作量门禁仍保留：

- 可见集合不变的小幅平移，正文 build/layout/paint 都为 0，包装描述变更为 0。

- 聊天两个方向的正文与时间消费点各构建一次，观察的 7 个固定节点构建为 0，Element 新增为 0。
- 复杂卡片刷新与激活的 33 个固定观察节点构建为 0，两种类型各连续换绑 32 次均零 Element 增删。
- 关闭预取和位置缓存的新视口：复选首屏可见 7 项、创建/绑定各 7 次；卡片可见 2 项、创建/绑定各 2 次。聊天既有末尾首屏测试继续通过。

## 五轮主机计时

环境：Flutter 3.47.5 / Dart 3.13.4，Windows，Debug JIT，Ahem 测试字体。测试串行、BelowNormal 优先级、每项 90 秒超时；整组交替比较耗时 285.7 秒，没有运行全仓基准。

每轮按内核 A/B、真实示例行 A/B 的顺序启动独立测试进程，共五轮。每个用例丢弃前 20% 的操作作为预热。下表是五轮 P50、P95 的中位数，单位为毫秒。完整逐轮结果见 [REUSE_RESULTS.json](REUSE_RESULTS.json)。

没有场景同时满足「五轮方向一致」以及「差值大于两侧轮间范围和基线 10% 的较大者」。因此本轮不把上述变化判为稳定的整体提速或整体退化；尤其不能挑选第一轮较大的降幅当成果。收到消息的中位数上升也完整列出，后续若真机同样回退，应单独归因。

这里计时包住的是 bind/scroll 到 pump 完成的主机墙钟，包含测试框架、JIT、CPU 绘制记录等成本，未覆盖真实 GPU 光栅、中文字形回退、输入重采样和屏幕实际呈现。2–7ms 的 pump 数字不能代替手机 UI 帧耗时。

## 测试与检查

465 个不同用例通过：核心、样式动画、模型及相关品牌回归 388 项，模型消费者与表单契约补充回归 17 项，示例回归 60 项。修改范围静态分析无诊断。没有运行全仓测试，也没有连接应用执行热重载。

核心组合首轮为 387 通过、1 个旧加载图标夹具失败；该夹具在基线也失败。改为测量实际 SVG 图标后，相关 6 项全部通过，已去重计入上述 388 项。进度自定义文案的夹具也明确尺寸，避免 Ahem 测试字体导致与本轮逻辑无关的溢出。

定向覆盖包括：

- RecyclerView 的已有回收、快速滚动、锚点、语义、滚轮、控制器、末尾首屏测试，以及新增结构批处理、预算、隐藏生命周期、局部换绑过渡测试。
- ModelValue 原有 7 项与新增 16 项；重入修正、同帧多输入、通道替换、取消回放、越界通知保护。
- TickerMode 7 项；选择品牌 11 项；ElStyle 动画与关键帧现有回归、移动焦点规则和品牌装配完整性。
- 表单双向绑定、校验与注销，以及分段、页签、折叠、步骤、滑块、日历、ListTile 与列表分组的模型契约。
- 真实复选/聊天/卡片、容器切换、首屏、最小消费点与结构保留；帧记录器窗口、尾批、复制与跨页面生命周期；全局滚动设置。

## 条件项的执行结论

| 备选方案 | 本轮结论 |
| --- | --- |
| 渐进式重行、空闲预热重类型 | 未默认启用。没有本轮真机证据证明尖峰来自不可预取的冷挂载；自动占位会改变内容显示与高度行为。先保留完整行和有预算的预取。 |
| 增大或下调重类型池 | 未全局修改。驻留与快速滚动门禁通过；容量应按具体模板的内存和环境切换成本决定。 |
| ModelValue 方案 B，拆分品牌所有观察通道 | 保留方案 A。跨子树观察者仍需要安全通知，没有证据支持扩大此轮契约变更。 |
| 普通 ElButton 去模型 Hook | 已测量：普通/toggle 都为 11 个 Element、1 个 StatefulElement，各一个直接模型 ListenableBuilder。未把单个监听构建器认定为滚动瓶颈，保留现有 Builder 的 Obs 契约，不为此新增模型协议。 |
| 把手机上“低 UI 耗时仍抖动”判为已解决 | 没有作此结论。本轮无真机 FrameTiming 或实际呈现 trace。 |

## 手机端记录入口

进入「系统设置 → 帧耗时记录」，选页面、容器和阶段，点击开始，在准备时间内返回目标页面。窗口结束后回到该页复制 JSON。记录器不会替用户切换容器，设置元数据与实际选择需保持一致。

报告包含 UI/raster/vsyncOverhead/totalSpan 的 P50/P90/P99/max、超过 B/1.5B/2B 的计数与比例、全部窗口内 vsync 间隔、静止窗口帧数和逐帧原始时间。提交号可通过 `--dart-define=GIT_COMMIT=<hash>` 写入，未提供时明确为 unknown。

若 UI/raster 都低但仍抖动，需要 Android FrameTimeline 的实际呈现与 deadline 数据；这一步不能被本轮无头测试替代。
