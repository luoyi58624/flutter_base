# 无头性能与回归验证

日期：2026-11-06。Flutter 3.47.5 / Dart 3.13.4，Windows，`flutter_test` Debug 测试进程。全程使用 `flutter_tester`，没有连接手机、启动前台应用或热重载。

本次能确定的是工作量减少与行为正确性：稳定 holder 不再更新同一包装描述，局部内容通知不再扫描全表。Debug `pump` 的主机耗时有波动，不能据此宣称手机帧率提升。

## 相同工作量的优化前后对照

基线为提交 `ee0c257` 中未优化的 RecyclerView 核心。仅将该目录的六个 Dart 实现文件保存到独立本地产物目录，使用同一份性能测试导入快照运行；没有回退或替换工作区源码。

测试内容为 10,000 条不同位置、标题、描述和勾选显示的数据，四种结构类型，通过 ValueNotifier 实际重新绑定。视口为 360×480；为单独比较可见滚动路径，两边均关闭预取和位置缓存。

步骤：

1. 初始挂载，验证没有全量创建 Widget 子树。
2. 在不改变可见集合的区间连续提交 24 帧微小位移，记录稳定正文实际 build、performLayout、paint 次数，以及四个稳定 holder 外包装的身份变化。
3. 连续 40 帧向前、40 帧反向滚动，每帧 88 像素，验证 holder 确实跨位置绑定、State 不反复挂载。
4. 对离屏的 4 项连续发送 16 次内容通知，单独记录类型查询次数和通知耗时。
5. 跳到第 9000 个索引，验证屏幕显示该位置的真实内容与稳定 ID；卸载后验证 State 全部释放。

两边完成相同绑定工作，正文已有的布局缓存和逐项重绘边界仍然生效。改进集中在不必要的包装更新，以及内容通知的全表类型查询；结构插入、删除、移动仍为保证位置相关类型正确而线性重建索引。

## 详细回归覆盖

本次相关子集共 71 项通过：

| 范围 | 数量 | 重点 |
| --- | ---: | --- |
| 回收池与原有核心回归 | 32 | 类型隔离、生命周期、payload、稳定 ID、布局、定位、回收释放 |
| 新增优化回归 | 15 | 动态数据、锚点、布局缓存、预取、环境变化、语义、物理和裁剪层 |
| 有界复用性能检测 | 1 | 上表的 10,000 条真实绑定及操作规模 |
| 新长列表示例 | 7 | 复选不串行、聊天历史/新消息、真实两端路由与窄屏布局 |
| 原文档滚动与原深链回归 | 16 | 四种文档滚动、压力倍率、目录定位、两端公共路由 |

新增优化回归具体覆盖：

- 10,000 条不同数据的复选状态按 ID 保存，实际复用相同 holder 后不串行。
- 稳定平移不重复构建、测量、绘制已有正文，子项自行展开和异步文本更新仍生效。
- 局部通知仅读取变更范围类型，结构变化仍正确处理依赖 position 的类型。
- 远跳后反向进入未知异高区域时，已有可见内容保持位置；小数尺寸和 padding 不重启稳定惯性。
- 预取结果保留绑定身份，含 LayoutBuilder 的子树合法布局，宽度变化后重测；关闭预取及缓存 0 正确收缩保留容量。
- 开启语义时坐标跟随滚动，隐藏池不暴露语义；全部/部分删除后旧语义与点击目标消失。
- 主题、宽度变化后驻留子树仍正确更新，没有 relayout boundary 断言。
- 自定义环境物理和最小/最大 fling 速度生效，真实拖动允许弹性越界并在松手后回弹。
- 连续滚动复用同一 ClipRectLayer，卸载后释放资源。

测试发现并修复的实际问题包括隐藏子树布局边界、删除项从 active 映射消失后漏退场，以及帧后直接布局 LayoutBuilder。预取现于可见布局后的合法布局阶段执行，预算包含真正的挂载/构建/布局，不能用低 UI 平均值掩盖帧后的同步工作。

示例测试通过 320、390、1280 宽的真实入口验证复选交互，并验证聊天阅读时历史插入/新消息追加保留锚点、底部跟随，以及通知文案变化不会撑高工具栏。原 payload 测试区分新位置的首次预取绑定与已有位置的重新绑定，继续严格检查载荷合并和无关已绑定项不重绑。
